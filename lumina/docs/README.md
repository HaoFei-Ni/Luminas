# 正式文档归档

本文档库按 **域（arc / eng / res / pm）× 编号（001 总纲 → 1xx 设计 → 2xx 专项 → 3xx 接口/体系）** 归档。
每个文档编号对应一个权威持有者（见下表），内容以对应 `.cursor/skills/lumina/*` 技能为准则撰写。

## 编号体系

| 域 | 总纲 | 子文档 | 权威技能（skill） |
|---|---|---|---|
| `arc/` 架构 | LUM-ARC-001 | 101 分层 / 201 算子 / 301 接口 | `luminas-arch-skill` |
| `eng/` 工程 | LUM-ENG-001 | 101 编码 / 201 构建 / 301 测试 | `eng-standard-skill` |
| `res/` 科研 | LUM-RES-001 | 101 消融 / 201 数据集 / 301 论文 | `research-skill` |
| `pm/` 项目 | LUM-PM-001 | — | — |

## 写作规则

1. **总纲（-001）是唯一入口**；派生文档只扩展、不推翻总纲。
2. 每个文档第 1 节写 `状态` 与 `关联编号`（引用其依据的 LUM-* / skill / commit）。
3. 分层与源码归属的口径以 `arc/LUM-ARC-101` 为唯一裁决点（四层 vs 三层争议在此收敛）。
4. 实验结论不写进 `docs/`：协议与官方案例 → `../research/`，归档产物 → `../experiments/`。
